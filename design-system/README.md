# 暖芽辅导班 · 设计系统交接

这个目录是**自动生成的**，由 `npm run build:design` 从 `h5/src/styles.css` 产出。不要手改这里的文件——改了下次生成就没了。

```bash
npm run build:design
```

## 目录里有什么

| 文件 | 用途 |
| --- | --- |
| `index.html` | **单页总览**，双击就能看完整套系统。发给设计师最方便的一份 |
| `foundations/*.html` | 色板、字号层级、圆角与间距 |
| `components/*.html` | 按钮、标签、卡片列表、数据展示、表单、导航、弹层 |
| `binding-code/*.html` | 绑定码输入框和牌子——本产品最独特的两个组件 |
| `screens/*.html` | 四个整屏：登录、家长今日、管理端看板、学员与绑定码 |
| `tokens.json` | 全部设计令牌的机器可读版本 |

每个 `.html` 首行都有 `<!-- @dsCard group="…" -->` 标记，这是 Claude Design 建卡片索引用的。文件本身是自包含的，直接在浏览器里打开也能看。

## 关键前提：预览里的样式就是线上的样式

每个预览文件都**内联了 `h5/src/styles.css` 的原文**，不是另写的一份演示样式。所以：

- 你在预览里看到的间距、颜色、圆角，就是家长手机上看到的；
- 每个组件旁边标了它的类名（`.btn--primary`、`.code-plate`），改动能一对一映射回代码；
- 如果哪天有人改了 `styles.css` 忘了同步设计稿，重跑一次生成脚本立刻就能看出差异。

## 改版时不能动的东西

这些不是审美偏好，是业务或平台的硬约束。改了会出功能问题：

**平台约束**

- **不能引 Web 字体。** 小程序包体装不下中文字体子集，规格里明确写了「包体不允许则降级为平台默认中文字体」。所以只能用系统字体已有的字重：常规 400、中黑 500–600、粗 700。不要指定 Light、不要用特殊字形。
- **图标必须是线性 SVG，禁止用 emoji 当功能图标**（`design.md` §4.5）。线宽统一 1.7，端点和拐角都是圆的。
- **微信小程序原生 tabBar 最多 5 项。** 现在两端各 4 项，改版别超。
- **底部要留安全区**（`env(safe-area-inset-bottom)`），全面屏手机上 TabBar 下面还有一条。
- **rpx 换算：375px 设计稿上 1px = 2rpx。** 标注请给 px，落地时统一乘 2。
- 触控目标最小 40px（按钮的 `min-height`），整行可点时最小 44px。

**业务约束**

- **家长端排行榜只能显示昵称或脱敏姓名**（张\*明）。这是隐私要求，不能为了好看改成真名。
- **通知发送失败绝不能用成功态。** 当前版本只记录站内提醒，尚未接入微信订阅消息；在获得微信接口成功回执前，不得显示“已通知家长”。
- **被冲正的积分流水加删除线但永不隐藏。** 账目要能倒查。
- **一屏最多一个主按钮、最多一个告警指标。** 现在告警色只给「待接」这一个状态用。
- **绑定码占位符用 `····-····` 而不是 `XXXX-XXXX`**，避免暗示「这里要填字母 X」。绑定码字符集不含 I、L、O、U。

**当前还没做的**

- 深色模式（令牌都是写死的浅色值，要做需要新增一套）
- 动效系统（现在只有弹层的 0.16–0.2s 淡入和上滑）

## 绑定码输入框：请重点看一下

这是家长第一次打开小程序就面对的唯一一个输入框，现在做了三层体验，改版时请保留：

1. **边输边归一化**——自动大写、第 5 位自动补短横、把误输的 `O` 纠正成 `0`、`I`/`L` 纠正成 `1`、全角转半角（中文输入法下全角是高频错误）；
2. **满 8 位先在本地验校验位**，错了当场变红，不发网络请求；
3. **校验位通过后才向服务端要一次脱敏姓名预览**，让家长确认「绑的是自家娃」再提交。

视觉上可以随便改，但这三层的时序不要动。

## 设计改完怎么交回来

按改动的层级，成本差很多：

**只改令牌（配色、圆角）** —— 最省事。给我新的色值表或改好的 `tokens.json`，我改 `h5/src/styles.css` 的 `:root` 一处，H5 和小程序两端同时生效。

**改现有组件的样式** —— 告诉我是哪个类名（预览里每个组件旁边都标了），给出改后的稿或直接给 CSS。

**新增组件** —— 给 390px 宽的稿，并列清楚全部状态（默认/按下/禁用/加载/空/错误）。少给一个状态我就得自己猜，猜错还得返工。

**改页面结构或流程** —— 这个要先聊，因为可能牵动接口。比如「把绑定码和关系放到两屏」就会改变 `POST /bindings/by-code` 的调用时机。
