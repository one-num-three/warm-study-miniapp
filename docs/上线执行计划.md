# 暖芽辅导班：微信小程序上线执行计划

> 文档状态：当前发布基线的唯一上线规划与验收入口。  
> 代码审查起点：`codex/integrate-complete-warm-study` / `5228d61`；本次整理提交后以该分支最新提交为准。  
> 更新日期：2026-09-05。

## 1. 结论

当前版本是“核心业务闭环完成、可受控内测”的 MVP，不是可以直接公开发布的版本。

已经完成的部分主要是业务功能和页面：家长绑定、每日作业、到班状态、积分、排行榜、兑换商店、错题集、老师权限、管理员审计，以及 H5 与原生小程序页面。

公开上线仍有硬门槛：发布代码源、生产配置、默认账号、微信订阅提醒、隐私授权、数据备份、真机验收和发布运维。

推荐路线：先用 H5 做受控内测验证流程，再完成微信能力和合规工作，最后发布小程序体验版和正式版。

## 2. 发布代码源

当前完整版本分支为 `codex/integrate-complete-warm-study`，整理前评估基线 HEAD 为 `5228d61`。

旧的 `codex/add-feature-guide` 分支不能作为最终小程序工程入口。合并发布基线之前，微信开发者工具应打开完整集成 worktree 下的 `miniprogram/`；完成主分支合并后，再统一从仓库根目录下的 `miniprogram/` 导入。不要导入仓库根目录本身。

## 3. 当前已实现能力

- 家长、老师、负责人三类身份登录。
- 绑定码生成、校验、脱敏预览、绑定和重置。
- 微信登录的 OpenID 稳定身份架构：首次绑定后，后续登录可以找回同一账号。
- 家长提交作业，老师逐项处理并结束当天作业。
- 到班、辅导中、待接、已接走状态流转。
- 积分流水、奖励、扣减、冲正、对账。
- 周榜、月榜、总榜。
- 商品上架、库存、兑换和撤销。
- 错题新增、查看和状态管理。
- 老师账号、角色权限、家长绑定审核、系统设置和审计日志。
- H5 端主流程和原生微信小程序页面。

## 5. P0：公开上线前必须完成

### P0.1 统一版本和发布流程

- 合并完整集成分支，建立唯一的 `main`/release tag。
- 确认 GitHub `main` 的内容不是旧 H5 原型。
- 保留微信开发者工具的本地偏好，但不把 `project.private.config.json` 提交到公开仓库。
- 发布前做一次 `git grep`/构建产物扫描，确认没有真实密钥、生产数据或演示登录入口。

### P0.2 生产配置

- 配置真实小程序 AppID、服务端 AppSecret 和固定随机身份盐值。
- 强制 `NODE_ENV=production`，缺少必要变量时启动失败。
- 将小程序 API 地址从 localhost 换成 HTTPS 域名。
- 在微信公众平台配置 `request` 合法域名，并在发布验收时开启合法域名校验。
- 固定 Node 22.9+ 运行时，数据库使用持久化磁盘。
- 提供明确的生产构建、启动、健康检查命令。

小程序网络请求需使用已配置的 HTTPS 合法域名；开发者工具的不校验选项只能用于开发。[微信网络文档](https://developers.weixin.qq.com/miniprogram/dev/framework/ability/network.html)

### P0.3 生产账号和种子数据

当前代码首次启动仍可能自动生成演示账号和演示数据；页面上的一键演示登录入口已移除，但本地 seed 仍使用默认凭据。生产环境必须：

- 默认关闭演示 seed。
- 增加一次性安全 bootstrap 命令创建首个负责人。
- 使用随机初始密码，首次登录强制改密。
- 负责人改密或提权后撤销旧会话。
- 从生产 H5、小程序和构建产物中移除快速登录和固定凭据。
- 生产数据库与演示数据库完全分离。

### P0.4 登录和安全底线

- 公开小程序只允许真实微信登录，不允许 device demo login。
- H5 若保留，应限制为邀请制/内测环境，或增加独立的稳定登录方式。
- 增加登录、绑定、密码错误的 IP/账号/设备限流和失败审计。
- 设置 Origin 白名单、可信反向代理和安全响应头。
- 按最小权限返回绑定码和儿童资料。
- 审计日志不得保存完整绑定码。

### P0.5 接娃提醒语义和真实送达

当前提醒接口只写入数据库，没有调用微信发送接口；页面上的“已通知家长”不能当作真实送达证明。

第一版推荐立即发送“预计可接时间”的通知。如果产品要求严格的“30 分钟后自动发送”，则必须新增持久化队列、定时 worker、重试、幂等、重启补偿、跨天和取消处理。

真实微信订阅流程为：家长主动授权订阅 → 服务端记录授权 → 服务端调用发送接口 → 记录每个收件人的成功/失败/未知状态。相关官方文档：[订阅消息总则](https://developers.weixin.qq.com/miniprogram/dev/framework/open-ability/subscribe-message.html)、[客户端授权](https://developers.weixin.qq.com/miniprogram/dev/api/open-api/subscribe-message/wx.requestSubscribeMessage.html)、[服务端发送](https://developers.weixin.qq.com/miniprogram/dev/api-backend/open-api/subscribe-message/subscribeMessage.send.html)。

在真实发送完成前，状态只能使用“已记录/待发送/发送成功/发送失败/结果未知”，不能用“已发送”代替数据库写入。

### P0.6 隐私和平台审核

项目涉及儿童姓名、作业、错题图片、家长关系和微信身份，必须补齐：

- 隐私政策和用户协议。
- 首次使用同意流程。
- `wx.login`、选图/拍摄等隐私 API 的授权处理。
- 数据用途、保存期限、删除/更正/导出和联系人。
- 家长撤回授权和儿童档案处理流程。
- 小程序类目、教育资质和审核材料。
- H5 同样的隐私说明和数据隔离。

参考：[微信用户隐私保护指引](https://developers.weixin.qq.com/miniprogram/dev/framework/user-privacy/)、[`wx.requirePrivacyAuthorize`](https://developers.weixin.qq.com/miniprogram/dev/api/open-api/privacy/wx.requirePrivacyAuthorize.html)。

### P0.7 数据安全

- SQLite 文件、WAL 和 SHM 放在持久化磁盘。
- 生产环境每日备份并加密。
- 至少完成一次全量恢复演练。
- 生产只运行单实例；规模扩大后再迁移到托管数据库。
- 发布前确认开发数据库和演示数据不会进入镜像或上传包。

### P0.8 真机和自动化发布门禁

- 微信开发者工具使用真实 AppID 编译。
- 开启合法域名校验后完成主流程。
- 至少一台 iOS 和一台 Android 真机验证登录、绑定、作业、图片和页面切换。
- 跨天测试不依赖执行时刻，且 E2E 命令返回 0。
- 若 Windows 仍暂时锁定 E2E 临时数据库，确认进程退出后再清理；该文件不在项目目录内。
- 体验版发布前完成一次回滚演练。

## 6. P1：首个真实班级前完成

- 图片压缩、MIME/大小/尺寸/数量校验；优先限制体积，后续迁移对象存储。
- 限制作业只能操作当天日期；历史补录必须有专门权限和原因。
- 提醒按当天日期过滤，不能显示昨天的提醒；禁止对未到班或已接走学生误发提醒。
- ETA 不能是过去时间，并保存完整日期时间。
- 作业项必须有文字或图片；错题必须有题干或图片。
- 保存每个未完成作业项的原因，或明确改成整单原因并同步规格。
- 锁定“输码即绑定/管理员审核”的唯一规则；生产建议默认审核。
- 排行榜默认脱敏或关闭实名展示。
- 新建老师时提供权限矩阵；教师列表按权限脱敏绑定码。
- 敏感业务变更与审计写入同一事务，或使用可靠 outbox。
- 增加 schema 迁移、graceful shutdown、结构化日志、告警和 CI。
- H5 增加退出并清除本机身份，避免共享电脑泄露儿童信息。
- 补充错题、图片、订阅、权限拒绝、弱网和恢复场景的 E2E。
- 更新 README、测试数量、seed 命令和 Node 版本说明。

## 7. P2：试运营后再做

- 桌面端宽屏布局和完整无障碍优化。
- 多个辅导班/多租户。
- 分页、搜索、统计报表和数据导出。
- 通知偏好、通知历史和更丰富的家长端设置。
- PostgreSQL/MySQL 等托管数据库迁移。

## 8. 执行排期

以下按一名开发者全职估算；业余推进约 4–6 周，不含微信平台审核等待。

| 阶段 | 时间 | 交付物 | 通过标准 |
| --- | ---: | --- | --- |
| D0 发布冻结 | 0–1 天 | 统一分支、提醒语义、绑定审核和排行规则 | 一个明确发布基线 |
| D1 生产基础 | 2–4 天 | HTTPS、环境校验、bootstrap、持久盘、备份 | staging 可重启和恢复 |
| D2 安全与数据 | 5–7 天 | 限流、权限脱敏、图片和日期校验、会话撤销 | P0 安全问题关闭 |
| D3 微信与隐私 | 6–10 天 | AppID、合法域名、隐私授权、真实登录 | 两台真机能完成登录绑定 |
| D4 提醒与验收 | 8–12 天 | 真实通知或明确降级、失败状态和重试 | 不再出现假“已发送” |
| D5 小范围试运营 | 13–15 天 | 3–5 个家庭连续使用 3 天 | 老师和负责人签字确认 |
| D6 正式发布 | 1–2 天 | 体验版、审核、灰度、回滚 | 低风险逐步放量 |

## 9. Go / No-Go 清单

以下任一项未完成，只允许标记为“内测版”：

- [ ] 完整集成分支已合并并打发布标签。
- [ ] 生产环境没有自动演示 seed 和固定登录凭据。
- [ ] AppID、AppSecret、身份盐值和 API 域名全部正确。
- [ ] 小程序真实 OpenID 登录后，第二次启动能自动恢复绑定。
- [ ] 提醒状态等于真实发送结果，或产品明确降级为站内/人工提醒。
- [ ] 隐私政策、授权、删除渠道和审核材料齐全。
- [ ] 数据库持久化、备份、恢复演练通过。
- [ ] iOS、Android 真机主流程通过。
- [ ] `npm test` 和 `npm run test:e2e` 均返回 0。
- [ ] 3–5 个家庭连续试用 3 天无 P0/P1 问题。

## 10. 目录整理原则

保留运行和维护必需内容：`miniprogram/`、`server/`、`shared/`、`h5/`、`scripts/`、根配置、有效测试、当前规格和本目录中的正式指南。

删除或忽略生成物：`node_modules/`、各 workspace 的 `dist/`、临时数据库、E2E 截图和测试报告。H5 先保留为业务逻辑测试床，不对外公开即可。

历史 CloudBase 设计、旧执行计划和内部代理记录不作为当前架构依据，应移入归档或从工作区移除；不要把它们和当前 Node + SQLite 方案混在正式指南里。
