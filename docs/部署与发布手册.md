# 部署与发布手册

## 生产拓扑

推荐先使用一台固定 Node 22.9+ 主机：HTTPS 反向代理提供 H5 静态文件和 `/api`，Node 服务单实例运行，SQLite 放在持久化磁盘。SQLite 未迁移到托管数据库前，不要启动多个后端副本。

## 上线前目标配置

真实值只放部署平台的密钥管理中，不写入 Git、小程序包或日志。下面是发布目标，不代表当前代码已经完成所有启动校验：

```text
NODE_ENV=production
PORT=8787
WARM_STUDY_DB=/持久化目录/warm-study.db
WARM_STUDY_WX_APPID=真实小程序AppID
WARM_STUDY_WX_SECRET=真实AppSecret
WARM_STUDY_IDENTITY_SALT=上线后永不更换的高强度随机值
WARM_STUDY_CORS_ORIGIN=https://你的H5域名
WARM_STUDY_SKIP_SEED=1
```

当前代码已经读取 `NODE_ENV`、`PORT`、`WARM_STUDY_DB`、微信凭据和身份盐；`WARM_STUDY_SKIP_SEED`、`WARM_STUDY_CORS_ORIGIN`、集中生产启动校验和安全 bootstrap 仍是待实现的发布目标。上线前必须实现这些能力：生产环境缺少 AppID、AppSecret、身份盐、数据库路径或允许的 Origin 时拒绝启动；设置 `WARM_STUDY_SKIP_SEED=1` 后，先执行一次性 bootstrap 创建负责人，再启动服务。

## 构建顺序

```bash
npm ci
npm run build:shared
npm run sync:shared
npm run build:wxss
npm run build
npm run typecheck
npm test
npm run test:e2e
```

生产发布前两条测试命令都必须返回 0。构建完成后扫描 `h5/dist/` 和小程序源码，确认没有演示账号、固定密码、localhost 或调试开关。

## 微信后台

1. 在公众平台配置与 `WARM_STUDY_WX_APPID` 相同的 AppID。
2. 在“开发管理 → 开发设置 → 服务器域名”配置 HTTPS `request` 合法域名。
3. 开发者工具本地调试可以临时关闭合法域名校验，体验版和正式版必须打开。
4. 订阅消息模板必须属于自己的小程序主体，并在家长主动操作时请求授权。
5. 在提交审核前准备隐私政策、用户协议、数据删除/更正渠道和类目资质材料。

## 备份和恢复

- SQLite 使用 WAL 时不能只复制主 `.db` 文件；应使用 SQLite backup/checkpoint 或停机后同时处理 `.db`、`-wal`、`-shm`。
- 每日加密备份，至少保留一份异地副本。
- 上线前做一次“新机器恢复 → 登录 → 查询作业/积分/兑换”的演练。
- 记录备份时间、恢复负责人和结果。

## 回滚

发布前保留上一版应用构建物和数据库备份。回滚顺序为：停止新进程、确认数据库备份点、恢复上一版服务、执行健康检查、再开放流量。数据库 schema 发生不可逆变化时不能只回滚代码，必须先完成迁移兼容设计。

## 故障处理

至少监控：服务存活、数据库可读写、登录失败率、权限拒绝、作业提交失败、兑换冲正、通知失败和磁盘空间。通知在没有微信接口确认时只能标记为“待发送/未知”，不能伪装成成功。
