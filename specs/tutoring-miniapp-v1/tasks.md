# 辅导班小程序 V1 实施计划

> 状态：待用户确认后进入执行  
> 需求引用：R1–R8 对应 `requirements.md`

## 1. 执行原则

- 一个里程碑验收通过后再进入下一个里程碑。
- 后端资源、权限和集合先准备，再开发依赖它们的前端。
- 每个敏感功能同时完成正常路径、重复提交、越权和失败回滚测试。
- 先打通一个完整用户旅程，再增加批量管理和视觉精修。
- 每项完成后更新本文件复选框，并保留需求追踪。

## 2. 建议节奏

按一名全栈开发者全职投入估算，V1 约为 6–8 周；若为业余时间开发，建议按 10–14 周安排。这里的时间是排期基线，不是上线承诺，实际受小程序主体、AppID、消息模板申请和微信审核影响。

| 里程碑 | 建议周期 | 可验收结果 |
|---|---:|---|
| M0 项目与环境准备 | 2–3 天 | 可在开发者工具打开并连接开发环境 |
| M1 身份、角色和学生 | 4–6 天 | 家长申请、管理员审核、角色隔离可用 |
| M2 作业与今日主流程 | 6–8 天 | 从提交作业到已接走完整闭环 |
| M3 接娃通知 | 3–4 天 | 预览、授权、发送、失败记录可用 |
| M4 积分与排行榜 | 5–6 天 | 奖励、调整、冲正、排行可核对 |
| M5 商店与兑换 | 4–5 天 | 上架、兑换、扣分减库存、撤销可用 |
| M6 错题集 | 3–4 天 | 上传、筛选、订正状态可用 |
| M7 管理强化与审计 | 4–5 天 | 权限配置、看板、审计和异常待办可用 |
| M8 联调、试运行与发布 | 5–7 天 | 真机验收通过并具备提审条件 |

## 3. 详细任务

## M0 项目和云环境准备

- [ ] 0.1 锁定基础资料
  - 确认小程序名称、主体、AppID、管理员微信号。
  - 确认辅导班显示名称、联系电话、接娃提示语。
  - 确认开发、体验、生产环境命名规则。
  - _Requirement: R1, R3_

- [ ] 0.2 初始化代码仓库
  - 创建原生微信小程序 TypeScript 项目。
  - 设定 `miniprogram/`、`cloudfunctions/`、`shared/`、`scripts/` 目录。
  - 配置 lint、format、typecheck、unit test 和环境配置模板。
  - 配置 `project.config.json`，不提交私密配置。
  - _Requirement: 全局_

- [ ] 0.3 准备 CloudBase 资源
  - 验证 CloudBase MCP 可用并完成设备登录。
  - 创建或确认开发环境，记录完整 EnvId。
  - 通过管理工具创建设计文档列出的集合和索引。
  - 配置默认拒绝、按绑定读取的数据库权限基线。
  - 创建作业、错题和商品的存储目录与安全策略。
  - _Requirement: R1–R8_

- [ ] 0.4 建立持续验证
  - 配置提交前类型检查和测试命令。
  - 建立开发数据初始化和清理脚本，只允许用于 dev。
  - 建立错误码、日志字段和 requestId 约定。
  - _Requirement: 全局_

### M0 验收

- [ ] 开发者工具可以编译并打开空壳小程序。
- [ ] 小程序明确连接 dev EnvId。
- [ ] 云函数能够识别测试用户 OPENID，但不向客户端公开原值。
- [ ] 未授权客户端不能读取管理集合。

## M1 身份、角色、学生和家长绑定

- [ ] 1.1 实现用户初始化
  - 使用微信原生身份自动创建/读取业务用户。
  - 处理首次进入、正常、停用三种状态。
  - 返回当前角色、权限和可访问学生摘要。
  - _Requirement: R1, R8_

- [ ] 1.2 实现学生档案
  - Owner 新增、编辑、停用学生。
  - 建立年级、昵称、家长备注和排行隐私字段。
  - 对姓名、手机号等信息实施最小返回原则。
  - _Requirement: R1_

- [ ] 1.3 实现家长绑定
  - 家长提交学生邀请码/匹配信息和关系说明。
  - 管理端展示待审核申请。
  - Owner 通过、拒绝或解除绑定。
  - 验证一对多、多对多以及重复申请处理。
  - _Requirement: R1_

- [ ] 1.4 实现老师和权限
  - Owner 将已初始化用户授权为 Staff。
  - 实现权限代码校验和账号停用。
  - 阻止删除或降级最后一名 Owner。
  - _Requirement: R8_

- [ ] 1.5 实现身份自适应壳层
  - 家长/管理员显示不同 TabBar 和首页。
  - 双身份用户可以显式切换，不自动混合数据。
  - 无身份用户看到绑定申请或等待授权状态。
  - _Requirement: R1, R8_

### M1 验收

- [ ] 家长审核前看不到学生数据，审核后只能看到绑定学生。
- [ ] Staff 不能管理角色，Owner 可以停用 Staff。
- [ ] 直接调用云函数不能绕过前端权限隐藏。

## M2 每日作业和辅导主流程

- [ ] 2.1 建立今日辅导记录
  - 创建每天唯一的学生辅导记录。
  - 实现待到班、已到班、辅导中、待接、已接走状态机。
  - 实现状态修正原因和审计记录。
  - _Requirement: R3, R8_

- [ ] 2.2 实现家长提交作业
  - 孩子和日期选择、动态添加科目项。
  - 支持文字、图片、备注和草稿恢复。
  - 上传前压缩图片，提交时显示明确进度。
  - 防止重复提交形成多份有效作业单。
  - _Requirement: R2_

- [ ] 2.3 实现管理作业池
  - 按日期、状态、学生筛选。
  - 提供待确认、需要补充、开始辅导动作。
  - 展示未提交作业学生名单。
  - _Requirement: R2_

- [ ] 2.4 实现作业处理页
  - 逐项开始、完成或标记未完成。
  - 填写老师反馈并结束当天作业。
  - 记录每项操作人和时间。
  - 为后续积分奖励预留“待奖励”状态。
  - _Requirement: R2, R4_

- [ ] 2.5 实现家长进度页
  - 今日首页展示辅导和作业状态。
  - 作业详情展示单项进度、反馈和完成时间。
  - 历史列表按日期分页加载。
  - _Requirement: R2, R3_

- [ ] 2.6 建立今日管理看板基础版
  - 聚合五种辅导状态人数。
  - 聚合作业未提交、待确认、进行中、已完成。
  - 每个数字可跳转到筛选后的名单。
  - _Requirement: R2, R3, R8_

### M2 验收

- [ ] 完整模拟一名学生从家长提交到管理员标记已接走。
- [ ] 非法状态跳转被服务端拒绝。
- [ ] 弱网重试不会创建重复作业单。
- [ ] 家长切换多个孩子时数据不串线。

## M3 接娃提醒

- [ ] 3.1 准备订阅消息
  - 确认可用消息模板及字段限制。
  - 配置开发/体验环境模板标识。
  - 实现通知授权状态展示和授权入口。
  - _Requirement: R3_

- [ ] 3.2 实现提醒预览
  - 提供 15/30/60 分钟和自定义预计时刻。
  - 显示接收家长、孩子、预计时刻和提示语。
  - 无订阅权限时给出明确替代建议。
  - _Requirement: R3_

- [ ] 3.3 实现可靠发送
  - 创建发送记录和幂等键。
  - 调用订阅消息并记录成功、失败或结果未知。
  - 防止相同预计时刻无确认重复发送。
  - 发送后将辅导记录推进到待接。
  - _Requirement: R3, R8_

- [ ] 3.4 实现提醒历史
  - 家长今日页显示最新预计时间。
  - 管理端显示发送人、时间、对象和结果。
  - 看板突出已提醒但未接走学生。
  - _Requirement: R3_

### M3 验收

- [ ] 真机验证接受授权、拒绝授权、模板发送失败三种情况。
- [ ] 连续点击发送只产生一个有效业务结果。
- [ ] 发送失败不伪装成成功，管理员可看到替代联系提示。

## M4 积分和排行榜

- [ ] 4.1 实现积分流水内核
  - 定义流水类型、来源引用、幂等键和余额快照。
  - 实现事务性加分、人工调整和余额查询。
  - 实现冲正而非删除。
  - 建立余额重算只读校验工具。
  - _Requirement: R4, R8_

- [ ] 4.2 接入作业奖励
  - 完成作业后显示待奖励入口。
  - 使用默认规则并允许 Staff 填写额外奖励理由。
  - 防止同一作业规则重复奖励。
  - 看板列出已完成未奖励学生。
  - _Requirement: R2, R4_

- [ ] 4.3 实现积分页面
  - 展示可用余额、本周成长、最近流水。
  - 明细区分获得、消耗和冲正。
  - 家长只能查看绑定学生。
  - _Requirement: R4_

- [ ] 4.4 实现排行榜
  - 周榜、月榜、累计成长榜。
  - 处理周期边界、同分、冲正和隐私隐藏。
  - 家长端脱敏，管理端完整显示。
  - _Requirement: R5_

### M4 验收

- [ ] 积分余额与有效流水求和完全一致。
- [ ] 重复作业奖励、负余额和无权限调整均被拒绝。
- [ ] 兑换测试扣分不影响周/月成长排行。

## M5 商品和兑换

- [ ] 5.1 实现商品管理
  - 创建草稿、编辑、上架、下架。
  - 管理积分价格、库存、限兑规则和商品图片。
  - 库存为零时显示售罄，不丢失商品历史。
  - _Requirement: R6_

- [ ] 5.2 实现家长商店
  - 按可兑换状态展示商品。
  - 商品详情显示积分、库存、规则和“现场找老师兑换”。
  - 不提供家长直接扣分按钮。
  - _Requirement: R6_

- [ ] 5.3 实现现场兑换事务
  - 管理员选择学生和商品，预览余额及兑换后余额。
  - 原子完成限兑校验、扣库存、扣积分和兑换记录。
  - 保存商品名称、图片和积分价格快照。
  - _Requirement: R4, R6_

- [ ] 5.4 实现撤销兑换
  - 仅 Owner 可操作并要求填写原因。
  - 原子恢复积分和库存，创建冲正流水。
  - 兑换详情显示完整关联记录。
  - _Requirement: R6, R8_

### M5 验收

- [ ] 并发兑换最后一件商品时只能成功一次。
- [ ] 任何失败均不会只扣积分或只减库存。
- [ ] 修改商品后，旧兑换仍展示原商品快照。
- [ ] 撤销后积分、库存和关联流水均正确。

## M6 错题集

- [ ] 6.1 实现错题上传
  - 支持图片或文字题目，科目、知识点、错误原因和答案。
  - 支持从作业详情带入学生和作业引用。
  - 家长与管理员入口使用同一数据模型。
  - _Requirement: R7_

- [ ] 6.2 实现错题列表和详情
  - 按学生、科目、知识点和状态筛选。
  - 分页和缩略图加载。
  - 展示创建人、订正时间和关联作业。
  - _Requirement: R7_

- [ ] 6.3 实现订正状态
  - 待订正、已订正、已掌握流转。
  - 已掌握后再次做错可回到待订正。
  - 保留完整状态事件。
  - 可选通过“错题已掌握”规则奖励积分。
  - _Requirement: R4, R7_

### M6 验收

- [ ] 家长无法搜索或打开其他学生错题。
- [ ] 图片失败可重试且不会创建空记录。
- [ ] 状态往返后历史事件完整。

## M7 管理强化、审计和体验精修

- [ ] 7.1 完善今日看板
  - 加入待审核绑定、未发积分、已提醒未接、低库存。
  - 按严重度排列异常，支持一键进入筛选列表。
  - 缓存聚合结果并设置合理刷新策略。
  - _Requirement: R8_

- [ ] 7.2 完善权限配置
  - Owner 可按 Staff 开关权限代码。
  - 所有管理按钮和服务端命令使用同一权限映射。
  - 建立权限变更审计和即时失效机制。
  - _Requirement: R8_

- [ ] 7.3 完善审计日志
  - 覆盖角色、积分、兑换、库存、学生停用和状态回退。
  - 展示操作者、前后值、原因、时间和 requestId。
  - 禁止任何客户端删除。
  - _Requirement: R8_

- [ ] 7.4 实施视觉系统
  - 落实自然手账式色彩、字体、间距和图标规范。
  - 完成家长首页、管理看板、成长页的非对称信息层级。
  - 表单和高密度管理列表优先保证效率与可读性。
  - 完成颜色、字体、图标和布局自查。
  - _Requirement: R1–R8_

- [ ] 7.5 完善通用体验
  - 空状态、骨架屏、失败重试、下拉刷新、分页到底提示。
  - 高风险操作二次确认和处理中防重复。
  - 图片预览、压缩和失败恢复。
  - 辅助文本不低于可读字号，触控区域满足移动端使用。
  - _Requirement: 全局_

### M7 验收

- [ ] Staff 只能看到并执行已授权动作。
- [ ] 敏感操作均能在审计日志中还原。
- [ ] 家长和管理员的核心动作最多三次点击可达。
- [ ] UI 自查无禁用色、禁用字体、emoji 功能图标和无意义对称卡片堆叠。

## M8 联调、试运行和发布

- [ ] 8.1 自动化质量门禁
  - 运行类型检查、lint、构建、单元测试。
  - 完成状态机、权限、积分、兑换核心集成测试。
  - 运行 CloudBase 项目代码审查并修复高风险问题。
  - _Requirement: 全局_

- [ ] 8.2 权限与安全测试
  - 家长 A 尝试访问家长 B 的学生、作业、积分、错题。
  - Staff 尝试角色管理、积分冲正和兑换撤销。
  - 停用账号尝试直接调用云函数。
  - 篡改商品价格、studentId、role 和 pointBalance 参数。
  - _Requirement: R1, R4, R6, R8_

- [ ] 8.3 事务与异常测试
  - 重复点击奖励、提醒和兑换。
  - 并发兑换、网络中断、函数超时、数据库冲突。
  - 通知拒绝授权、发送失败和结果未知。
  - 图片上传一半失败、切后台和恢复。
  - _Requirement: R2–R8_

- [ ] 8.4 真机完整验收
  - iOS 家长账号走完整流程。
  - Android Staff 账号处理完整流程。
  - Owner 检查权限、积分、兑换和审计。
  - 模拟一个孩子有两个家长和一个家长有两个孩子。
  - _Requirement: R1–R8_

- [ ] 8.5 小范围试运行
  - 先录入 3–5 名测试学生运行 3 个真实辅导日。
  - 每日核对作业状态、提醒记录、积分流水和接走状态。
  - 收集妈妈和两位家长的操作阻塞点，只修复 V1 核心问题。
  - _Requirement: 全局_

- [ ] 8.6 发布准备
  - 准备隐私政策、用户协议、隐私接口说明和类目材料。
  - 清理体验环境测试数据，检查生产索引和权限。
  - 固定生产 EnvId、消息模板和版本号。
  - 通过微信开发者工具上传体验版并完成最终真机验证。
  - _Requirement: 全局_

- [ ] 8.7 提审与上线
  - 提交微信审核并记录版本说明。
  - 审核通过后选择低峰时间发布。
  - 上线首周每日检查错误日志、通知失败、余额差异和慢查询。
  - 准备回退版本及人工联系方式。
  - _Requirement: 全局_

### M8 上线门槛

- [ ] 严重级和高优先级缺陷为零。
- [ ] 主流程成功率满足试运行要求，无账务不一致。
- [ ] 家长跨家庭越权测试全部被拒绝。
- [ ] 积分可重算，兑换可对账，敏感操作可追溯。
- [ ] iOS、Android 真机和微信体验版均通过。

## 5. 项目责任建议

即使由一个人开发，也建议明确以下责任帽子：

| 责任 | 负责人建议 | 产出 |
|---|---|---|
| 产品确认 | 妈妈 + 项目负责人 | 规则、文案、验收决定 |
| 技术实现 | 开发者 | 小程序、云函数、数据和测试 |
| 运营配置 | 妈妈 | 学生、老师、积分规则、商品 |
| 真机验收 | 妈妈 + 1 名老师 + 2 名家长 | 真实流程反馈 |
| 发布审批 | 小程序主体管理员 | 隐私材料、审核和发布 |

## 6. 开发开始前仅需准备的外部材料

- 微信小程序 AppID 和主体管理员配合。
- CloudBase 可用环境或创建权限。
- 妈妈的微信账号，以及至少一个家长和一个老师测试账号。
- 辅导班名称、联系电话、接娃提示语。
- 首批学生测试数据，不使用真实敏感信息也可。
- 3–5 个测试商品名称、积分价格和图片。
- 作业完成、表现优秀、错题订正的默认积分规则。
- 微信订阅消息模板申请所需内容。

## 7. 首次试运行数据建议

- 5 名学生，其中一名绑定两个家长。
- 2 名 Staff，一名只有作业权限，一名同时有兑换权限。
- 5 个商品，包含上架、下架、低库存和售罄状态。
- 每名学生 3 天作业记录和 3 道错题。
- 至少制造一次提醒失败、一次重复奖励、一次积分不足和一次库存冲突，用于验证防护。
